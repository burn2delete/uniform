## Purpose and contracts

Reconcile the [240 original contracts](../../docs/document-inventory.json)
with the existing component implementation task authorities. D0, D1, D2, D3
and D9 govern behavior identity, architecture, ordering, terminology and

## Requirements and acceptance

Every source obligation must resolve to an existing task, a reviewed task
correction, or an explicit actionable missing interface. Repeated obligations
retain their source facets and map to the same behavior only when their
observable operation and acceptance conditions agree. A shared artifact or
implementation provider alone does not establish an alias.

Preserve existing task IDs, scoped accepted results, historical attempts,
source byte identities and review qualifications. Open and unassessed work
stays in the accepted scope and receives no completion credit. Source scope
questions and missing implementation evidence are different conditions.

The completed baseline must have independent source conservation, task
entailment and cross-family overlap review. Its accepted-complete/total count
and unweighted ratio must refer to one exact source/task tuple. Component,
document, phase, proposal and facet counts are separate inventories.
