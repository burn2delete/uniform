# First PMK source and receipt hooks

`gravity.pmk.hooks` supplies the three workload-specific hooks consumed by the
existing C-exclusive/L controller. It adds no controller, runner or broker.
Constructing hooks or their normal I/O map performs no I/O or target execution.

The bookend hook checks independently frozen consumed-file hashes, reads actual
Git head/tree/tracked status with the pinned system Git, captures current source
and loader inputs, and observes ordered classpath/JAR, executable, environment
and explicit direct-Java configuration identities. It calls the existing full
fifteen-selector preparation before projecting the first request again. Both Git
observations, the reconstructed request and runtime must match the frozen tuple.
It returns the controller's exact bookend only after these checks. A frozen
method still needs an independently reviewed complete consumed-file inventory;
these checks are consistency evidence, not binary/runtime authentication.
Git tracked-status observation explicitly disables ahead/behind work. The first
workload's outer method binds effective Git settings in output order, except
`branch.<name>.remote` and `.merge` administration; head/tree/tracked-status
observations request no branch tracking. Other settings and duplicate-value
precedence remain checked. Raw common-config hashes remain observations, while
compiler/source/runtime file pins remain exact. This avoids treating peer branch
administration as a compiler input or a global writer exclusion.

The capture hook reads the actual normal machine-result file under the declared
host capture bound. It requires strict UTF-8, one EDN map without tagged values
or trailing forms, and normal exact-selector attribution. It does not invent
counters or replace a failed result with success.

The publication hook checks the operation/request identity, retains passed or
failed status, and records SHA256s of bounded stdout/stderr bytes. It writes
stdout, stderr and then the terminal receipt using CREATE_NEW. All sizes are
checked before any write. A collision or partial native write failure escapes;
there is no overwrite or automatic retry. Only observational controller receipts
use this encoding; compiler artifacts and their codecs are unchanged.
Missing capture is explicitly unavailable on a failed terminal receipt and
cannot be published as a passing capture.

Core controls use fake I/O and the existing fake C/L lifecycle. They cover dirty,
foreign or changing Git/source/file/runtime inputs; changed reconstructed
requests; wrong selectors; malformed UTF-8/EDN and oversized capture; foreign
terminal identities, partial writes and duplicate publication. Composition
controls preserve reverse L/C release and failed status on a late source change.
No normal I/O, broker/process interface, owner or target executes in controls.

The source hooks do not establish participant coverage, output absence/history,
outer-supervisor containment or platform admission. Their actual file/runtime
pins and entrypoints must be bound to the one reviewed method before submission.
The first genuine PMK selector remains UNRUN until all existing requirements are
met. No distinct-root exception, H root or generic controller is introduced.
