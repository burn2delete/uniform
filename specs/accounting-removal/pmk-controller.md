## Implemented method

The controller first checks the independently expected/observed first-request
binding and exact generated launcher/CWD. Direct Java selects the pinned Java
executable, ordered classpath and 2 GiB heap explicitly; it performs no Clojure
launcher/dependency configuration discovery. Its generated expression calls the
normal development runner once with the exact namespace/selector and non-fail-fast
selection. The normal machine sink creates a new bounded result file. The
logical `:dev-test` argv remains in the retained request for attribution.

The method then records source bookends, acquires the explicitly configured
guards in order and validates each live lease before starting one child. Normal
ports lazily bind the existing SH-01 broker and parallel runner. A canonical
guard opens only an existing regular non-symlink file and uses `tryLock`; it
never creates a new lock root/file. Broker validation requires zero reported
stale-ticket recoveries before child start. This is a rejection rule for the
normal new admission, not a stale-operation recovery procedure.

Each bookend must match the exact request source/checkout/input/parent identities,
runtime, CWD and request/binding digests; stable Nil or foreign values refuse.
After the initial bookend and before acquisition, the normal claim port checks
that the four output paths are absent and atomically creates the terminal path's
`.started` marker with `CREATE_NEW`. The marker is retained on failure. A duplicate
claim cannot acquire, start or republish into the original operation. Output
directories must already be configured; the claim port creates no directories.
The first-request contract now binds eight port identities, including `:claim`.
The controller additionally requires the normal `claim-operation!` Var and its
source-bound entrypoint identity; substituting a function that only advertises a
successful claim refuses before ports. Core controls explicitly replace that
Var root with a synthetic CAS, never its normal filesystem implementation.

The monotonic deadline is checked before/after acquisition, after startup and
process supervision, and after release. Remaining time is passed to broker and
process ports. Capture must contain the exact normal one-test machine result,
positive assertions and matching source bookends. Nonzero exit, timeout,
truncation, failed capture, incomplete cleanup, an uncertain terminal result or
source drift cannot pass. A supervisor's already-attempted cleanup is never
repeated. An exception with an unhandled owned child triggers one cleanup attempt.
Guards are released once in reverse order, including partial acquisitions and
validation failures. Release failures prevent success; terminal publication
occurs once after release and preserves the original error if publication fails.
