# OWN facade current Reader invocation repair

This source candidate addresses the public interface dependency identified by
the frozen OWN-02 direct-owner selector report. It does not change the frozen
child05e9, controller5f7, PR582, FIRST request3de1a75e, ACC10 producer or ACC11
consumer. It establishes no genuine owner execution, profile adoption or OWN
closure. The current source is a proposed successor to the historical facade.

## Interface and owner bindings

`run-pipeline` retains its historical behavior when Reader selection is omitted.
The explicit `:reader :development-current` option matches the existing public
Core option. Only this route accepts optional `:module-inputs`; default inputs
are the existing empty SH06 module-input record. Caller-supplied invocation,
internal operation, context or unknown request keys are rejected. The host resolves
the existing Reader source path and asks its owning verification-invocation API
for the selected source/plan/function identity. The label alone is never the
cache identity. Module inputs pass the actual owning module-view validation;
nonempty module sets are verified under the same existing owner invocation scope.

The facade forwards that same host-owned invocation to the existing constructors:
C2 seven arguments, precomputed-C2 C3 seven arguments, Macro three arguments,
module-aware Resolve five arguments, and Core two arguments. Immediate parents
and the original internal C3 product authority remain unchanged. No equivalent
compiler implementation, selected-source evaluator or new digest codec is added.

Fast replay uses the actual owner APIs with the same invocation. C2 keeps its
two-argument validator and also authenticates its selected Reader through the
existing C3 Reader-artifact view. C3 takes three arguments, Macro two, Resolve
three with its existing legacy-context identity, and Core two. Module inputs
embedded in cached Resolve/Core must equal the selected inputs before replay.
An invalid immediate parent still fails the original parent gate before replay;
a rejected cached product is evicted before reconstruction.

## Identity, bookends and publication

Current-route cache keys include actual selected Reader source content/count,
plan and function semantic hashes, and the ordered IDs of owner-validated module
artifacts. Existing source/project-context identity and parent IDs remain in the
key. Legacy keys remain byte-for-byte structurally unchanged. Fresh still bypasses
the store and stages no cache entries. The selected Reader binding and verified
module inputs are checked again after source execution and before pending cache
publication. Drift or any original owner diagnostic prevents publication.

## Compiler-free evidence and limits

`tools/artifact_pipeline_invocation_test.clj` evaluates only the actual facade
orchestration forms in isolated namespaces, with explicit fake owner functions
and products. It does not load Bootstrap, the facade namespace, a Reader plan,
normal broker/runner or an owner constructor. The standalone tools location follows
existing Clojure tooling tests and leaves the FIRST request's frozen parent test
loader directory unchanged; no denied worktree creation is retried or replaced.

The twelve controls cover the closed/default API, actual owner selection,
constructor arities and unchanged parent objects, current replay arities, each
Reader identity field, module identity/substitution, per-owner replay rejection,
fast hits versus fresh bypass, selected-source bookend drift, original diagnostic
preservation and nonpublication. They pass 12 tests/82 assertions. The unchanged
parent/cache controls pass 5/134 and the language-boundary gate passes 6/11.
Initial test-only delimiter, local-name shadowing and stub-arity errors were
corrected before this result; none invoked a genuine owner.

These controls prove orchestration behavior under explicit stand-ins, not authentic
compiler products or current Reader runtime support. Independent affected source
review and any later genuine execution remain separate evidence. Source/method
acceptance of FIRST request preparation does not accept this new facade source;
the first frozen direct-owner selection is not silently retargeted to it. Exact
child/CWD/runtime/profile/platform assessment must be reconsidered for any later

The original current-parent profile, retained-owned-descendant terminal interface,
