# Checked-core semantic products and declared digests

This increment moves the eight existing Core semantic identity, mutation/error
record, declared-digest and result materialization functions into
`gravity.checked-core`. D1, D2, D3, D9, L2, C1, C3-C6, C15, B13, BOOT8 and TEST2
govern this boundary. Core's semantic projection identity remains distinct from
the authenticated upstream artifact identity and physical source provenance.

Inputs are existing Core template/preimage records, declared digest requests,
resolved references and explicit current-source Gravity runtime operations.
Outputs are semantic mutation/error/node records, normalized identity preimages,
ordered SHA-256 digest identities and materialized template data. Every digest
purpose, exact ordinal/schema join, native carrier and failed Gravity result
must retain its existing validation and C6-VERIFY diagnostic. These are semantic
and format requirements, not work accounting or input quotas.

Bootstrap keeps actual Core admission, proof transactions, publication and
historical migration checks. Public APIs grant no artifact admission authority.
Compatibility names/arities and explicit callable Var ports remain intact;
construction and receipt epochs qualify every new stage/operation root. A
materialized template is not an admitted Core or backend artifact.

Acceptance requires actual Gravity Core template/digest/result emission and
real malformed digest rejection, complete before/after product comparisons,
identity/provenance and purpose/order adversarial tests, appropriate
regressions, independent review, exact-head CI and clean integration preflight.
No historical denied Reader, migration, native or external-capture action is
retried. This early draft grants no acceptance, release, performance,
self-hosting or seed-retirement support.

The extraction moves eight public APIs: `semantic-mutation`,
`semantic-error-transfer`, `semantic-error-handler`, `semantic-node`,
`semantic-identity-preimage`, `resolve-digest-preimage!`, `digest-requests` and
`resolve-result`. The stage now has 46 public functions and four private helpers.
Its explicit contract records inputs, outputs, purpose/ordinal diagnostics and
admission:none. Compatibility names/arities, callable Var ports and all late
construction/receipt roots are preserved. An unused stage digest-declarations
argument is named with an underscore; the compatibility argument is unchanged.
