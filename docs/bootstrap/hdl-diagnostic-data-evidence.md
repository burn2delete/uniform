# HDL native diagnostic policy data

## Contract boundary

D1, D2, D3, D8, D9, C1, C15, B1, B9, B13, B14, BOOT8 and TEST2 govern
this extraction. Three existing native functions move to gravity.backend.hdl:
source-overrides, missing-fact and signal-id. Trusted native module metadata
and diagnostic ids produce borrowed overrides and existing diagnostic context
labels. The stage imports only clojure.core; Bootstrap consumes the stage.

The stage owns override precedence and native rule-context defaults. Existing
wrappers retain their arities and late interposition. Refusal decisions,
failure construction, catalog streams, source admission and publication stay
with existing owners. Whole-file reconstruction preserves the original lookup
bodies and all surrounding component/Bootstrap bytes except delegation.
The component contract registers the source, consumer and standalone test.
The existing contract-derived ownership test adds only the HDL native owner
and its actual-registration, wrong-slice and unknown-owner controls.

## Artifacts and checks

Focused tests emit and read back an actual B9-MANIFEST diagnostic for an empty
malformed native artifact, retaining supplied source context, the hardware
profile and SystemVerilog target. Catalog records retain supplied input
identity, source context, order and serialized determinism. Catalog rows are
compatibility examples, not ten observed semantic failures. Frozen-parent and
candidate captures compare complete original source records, lookup policy,
overrides, catalog streams, malformed-input observations and ten actual
override refusals, with source and malformed-input digests recomputed.

Data tests cover precedence, false/empty overrides, borrowed identity, unknown
defaults and late stage/wrapper lookup. The correctly launched parent capture
completed before editing. An initial extraction helper used a nonexistent
component filename and failed before writing its three implementation files;
the helper and error report are retained. The filename was corrected; no
compiler mode, Gravity source form, pin or admission fact was changed to obtain
a pass.

## Unsupported boundaries

This is native diagnostic data extraction. Full Gravity B9 compilation,
verified hardware/domain ingress, HDL emission, simulation, synthesis, width
or numeric checks, clock/reset/CDC validation, finite-control legality,
interface/timing validation, downstream handoff, source authentication and
public diagnostic redaction remain unsupported. Existing signal, proof,
complete and rejected labels are data, not hardware evidence or authority.
No native broker, restricted factory, default frozen Reader,
package/archive/release builder or Attempt30 route executes. Migration,
release, self-hosting and seed retirement are not claimed. Independent review,
own CI/artifacts and exact clean current-main integration preflight remain
required.
