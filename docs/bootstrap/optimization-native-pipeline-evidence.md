function-root evaluation behavior. Existing facade and leaf entry points remain
compatibility APIs; their operations context and policy remain unchanged.

The eight planned APIs are native-source-overrides,
native-source-overrides-artifact, native-diagnostic-catalog,
native-artifact-base, native-validate!, native-capability-proof,
native-source-artifact and native-file-artifact. Inputs are trusted native
configuration, source/path/module, C12-shaped parent, pass/decision/evidence
records, and explicit late operation suppliers. Outputs are the original native
C13 artifact, diagnostics, projections, complete marker or ordered refusal.
The stage owns the algorithms and refusal selection. Existing operations own
source input, shared record construction, diagnostic transport and all admission.

Core feeds Optimization, which is consumed by the native C13 compatibility
leaves. The stage imports no Bootstrap or legacy C13 facade. Zero-argument
function suppliers preserve lookup before argument evaluation, including late
redefinition of existing private span, digest, failure and construction helpers.
Suppliers are trusted seed implementation dependencies, not proof providers.

optimizer or genuine C11/C12 input admission. Complete, passed, accepted,
proof, check-elision and verifier labels remain original fixture data. No new
pass executes, no safety check is erased and no cache is actually invalidated
by constructing these records. Existing vacuous/truthy predicates remain.

grant, unsafe approval, target legality, native backend execution, performance,
release, migration, self-hosting or seed-retirement support is established.
Held broker/factory, private JVM, package/release, default frozen Reader and

pending backend/Safety integration source is edited by this slice.
