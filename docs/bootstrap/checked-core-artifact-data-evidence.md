# Checked-core candidate data, presentation and diagnostics

This increment moves the four existing Core candidate-data, decimal
presentation and diagnostic construction functions into `gravity.checked-core`.
D1, D2, D3, D9, L2, C1, C3-C6, C15, B13, BOOT8 and TEST2 govern the boundary.
Inputs are existing resolved templates, explicit literal descriptors, rejected
Gravity results and request/rule-specific data plus seed operations. Outputs are
candidate Core maps, explicit host presentation views and the existing thrown
C6 diagnostic construction records.

The canonical-artifact helper assembles data; it grants no Core owner admission,
proof, publication or release authority. The decimal view must retain its
explicit warning: its host values differ from the authenticated identity
preimage, so it is not a canonical authenticated Core. Diagnostic constructors
preserve stable rule/fact/provenance data and existing digest-request fields;
they are not a new safe public diagnostic projection or publication path.

Bootstrap retains actual owner verification/admission, proof transactions,
publication and historical migration checks. Compatibility names/arities,
explicit callable Var ports and late construction/receipt roots stay intact.
No accounting, input quota, source-pin renewal or new host runtime is introduced.

Acceptance requires actual candidate/view emission from a real current Gravity
template, real rejected-template diagnostics, complete before/after products,
identity/provenance/decimal/diagnostic adversarial checks, proportionate
regressions, independent review, exact-head CI and clean integration preflight.
No historical denied Reader, migration, native or external-capture action is
retried. This early draft grants no acceptance or full C15/Core/backend/release,
self-hosting or seed-retirement completion.

`raise-diagnostic!` and `request-diagnostic!`: 50 public functions and four
private helpers in total. Every API retains admission:none. The existing

changing the seed operation map. All four compatibility names/arities and
late stage/compatibility roots are retained. An unused stage source-path
