# Checked-core form and source projection

This increment moves the existing C6 form/source projection helpers into
`gravity.checked-core`: source-path/span/value classification, C2 literal and
occurrence alignment, deterministic projected identities, macro-origin traces,
form trees, source collection order and parameter binding paths. D1, D2, D3,
D9, L1, L2, C1, C2, C3, C4, C5, C6, C15, BOOT8 and TEST2 govern this boundary.

Inputs are existing owner-verified C5/syntax/reader records and explicit seed
operations. Outputs are projection records and identities, exact generated
origins, source-order records and private decimal-occurrence construction
state. The retained reader occurrence and decoding evidence must determine
Character kind, decimal scale and map/set evaluation order. Host materialized
collection order must not replace that source evidence. Exact parent/child,
occurrence and decoding-record bijections remain mandatory.

Bootstrap retains actual owner admission, request/authority binding, migration
checks, proof transactions and publication. Internal occurrence/mismatch helpers
stay private; public APIs declare admission:none. Stage, operation and helper
roots must qualify existing construction/receipt epochs. This extraction adds no
project accounting or input quotas and changes no source-language semantics.

Acceptance requires real current-reader C5 products in both source spellings,
real emitted projection/request data, actual C6-ORIGIN rejection of forged
source evidence, complete before/after output and diagnostic comparisons,
focused identity/origin/ordering/literal and adversarial checks, appropriate
regressions, independent review and exact clean integration preflight after CI.
No historical Reader, migration or native-launch refusal is retried or renewed.
Full Core lowering, authenticated Core artifact publication, typing, safety,
release, performance, self-hosting and seed retirement remain unsupported claims.
This early boundary document grants no acceptance.
